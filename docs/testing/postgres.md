# PostgreSQL test rationale

All cases use the public Storage API with an actual PostgreSQL server selected by RELANOX_TEST_POSTGRES_URL. Each test owns a fresh schema; restart cases reopen independent pools against that same schema. No database or cluster is deleted. Absent a URL, PostgreSQL cases explicitly skip; CI must provide it.

For every case: observable behavior / credible regression / why existing coverage misses it / unused production seam.

1. Shared acceptance and dedup: snapshots stay immutable and duplicate sources return the original request / missing unique key or serialization / no PostgreSQL coverage / none.
2. Shared scoped FIFO claims: only oldest unfinished work claims; same claim key replays; foreign endpoints cannot claim / absent FIFO or scope predicate / acceptance does not claim / none.
3. Shared completion: frozen target validation, final uniqueness, atomic outbound and idempotent replay / separate commits or missing invariant / claims do not create finals / none.
4. Shared delivery leases: one lease under concurrency, fenced settlement, durable chunk receipts and current-chunk attempts reset, unknown and safe-account recovery / missing fencing or cumulative attempts / completion does not send / none.
5. Shared processing recovery: claims do not expire and explicit recovery revokes prior tokens / conflating processing claims with worker leases / delivery case concerns outbound / none.
6. Shared protocol state and admin: namespaced CAS, expiry/prefix lists, aggregates and pagination / unconditional writes or cross-owner read / business cases do not use protocol state / none.
7. Shared retention: pending/undelivered survive, sent text redacts, source/final replay survives and altered finals conflict / erasing rows or digest / other cases retain text / none.
8. Shared rejected dispatch and retries: versioned explicit recovery releases FIFO, retryable preserves chunk identities and due time / rejection cannot recover or retries advance chunk / unknown case does not reject / none.
9. Shared JSON rollback: non-JSON data rejects and does not commit partial final/outbound / permissive stringify or partial transaction / invariant conflicts do not exercise exceptions / none.
10. Shared failure retention: failure replay is scoped and failed redacted input cannot recover / missing terminal or tombstone guard / prior cases cover claimed and completed / none.
11. Independent pools and restart: explicit/idempotent migration; concurrent scans grant one lease; reopened pools turn expired dispatch unknown and preserve long claims / reliance on process-local state, missing serializable retry, auto-migration / shared cases use one pool lifecycle / none; schema configuration has a production purpose.
12. Cross-pool contention: simultaneous dedup, endpoint claims, global final IDs, state creates and state updates have one winner with no partial outbound / check-then-write in READ COMMITTED or absence of predicate protection / single-pool contract does not stress independent clients and multiple unrelated inbound rows / none.
13. SQL filtering and bounded administration: due scan reaches eligible endpoints behind blocked FIFO rows, excludes pull endpoints, limits results; relevant status/scope/pagination and literal state-prefix/expiry filters; bounded retention preserves pending work / fetching a bounded prefix before filtering or conflating status filters / shared fixtures contain too few competing endpoint and prefix cases / none.
14. Configuration boundary: environment SecretRef, identifier and pool/time bounds validate and missing secrets reject without credential disclosure / raw URL accepted into durable config or untrusted identifier interpolation / storage operation suites use valid config / none.
15. FIFO insertion during active work: same-timestamp lower IDs cannot claim or dispatch while an existing endpoint has a processing claim or started dispatch; the original leased notification remains claimable and unrelated endpoints progress / ordinal-only predecessor check either creates another active task or prevents the original task from claiming / prior concurrency cases accept all input before claim and use distinct timestamps / none.
16. Partial-send restart: a receipt and current chunk survive pool shutdown; an expired unacknowledged send remains unknown until recovery; acknowledged retry resumes the same chunk identity and preserves earlier receipts / flushing only on close, resetting chunks or auto-retrying unsafe sends / shared send cases do not reopen a pool between chunks / none.

Driver implementation follows node-postgres [transactions](https://node-postgres.com/features/transactions), [parameterized queries](https://node-postgres.com/features/queries), and [pool lifecycle](https://node-postgres.com/apis/pool): one checked-out client per transaction, rollback and release on failure, pool.end on close. PostgreSQL Serializable serialization/deadlock errors retry the entire local transaction; no external side effects occur inside it.
