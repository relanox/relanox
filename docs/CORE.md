# Core assembly API

`@relanox/core` depends only on SDK, Hono and Zod. `createCore` receives `{ config, storage, channels, agents, observe?, worker? }`. It does not create storage, initialize its schema, start listeners/timers, resolve credentials, or start/stop plugins. CLI initializes storage on run before checking health; offline diagnosis only inspects storage, assembles plugins, creates core, starts connections with a process AbortSignal, and calls processDue periodically. Shutdown sets accepting=false, stops the background loop/connections, closes storage and bounded observability export.

`channels` is a ReadonlyMap keyed by configured account ID with one ChannelPlugin instance per account. `agents` is keyed by `dot`/`grok`, one instance per kind. Plugin config generics are erased to unknown at assembly; typed plugin factories still validate their own schemas. Metadata must match configured kind, SDK major 1 and node runtime. All account and **per-endpoint** agent configs are validated before any setup. Account setup gets the parsed plugin configuration and a copy of its original static account. Agent setup gets all its original endpoint configs and `{}` as the third argument; per-endpoint validateConfig never validates `{}` as an agent-wide configuration. Agents validate their frozen endpoint configs again as needed when dispatching.

`validateConfig(unknown)` validates the strict SDK-shaped static JSON. IDs are safe URL namespace segments, bindings reference existing accounts/endpoints and unique `(accountId,chatId,threadId)` tuples, and allowlists are explicit nonempty sender IDs. A missing binding rejects; an account allowlist and optional binding allowlist must both permit the sender. There is no implicit thread fallback/wildcard. Configuration contains only static JSON; plugin schemas must require SecretRefs for credential fields. `secretRefSchema` and `resolveSecretRef(ref,environment)` let assembly/plugins resolve at use, without core reading process.env. Core persists copies of **original** endpoint JSON/options/SecretRefs and durable targets, not validator results or resolved secrets. Plugins must not put credentials into target.data/context. Configuration changes require process recreation; old persisted endpoints continue dispatching to the original destination while resolving current referenced environment values.

HTTP mounts use `/channels/<accountId><path>` and `/agents/<agentId><path>`; path `/` mounts the namespace root. Example channel `/webhook` becomes `/channels/bot/webhook`; agent `/mcp` becomes `/agents/grok/mcp`. Plugin handlers see the full original URL, including this prefix. Mount paths accept literal safe segments and a terminal `*`, never traversal/query/fragment. Duplicate routes reject setup. Core handles route errors with a redacted 500. HTTP bodies are buffered as exact bytes up to maxHttpBodyBytes, including chunked/dishonest Content-Length input; oversized inputs return 413, incomplete bodies hit callTimeoutMs and return 408. No signature decoding or reserialization occurs. Protocol plugins authenticate before Host calls and enforce their transport-specific body/host/origin/time limits. Management health/metrics routes are mounted by CLI on its separate listener, not exposed by the business fetch API.

ChannelHost pins source+target account/channel, validates bounded Unicode text and serializable context, checks allowlists/binding and waits for acceptInbound before returning. Storage owns stable event deduplication. AgentHost.forPrincipal intersects authenticated endpoint IDs with configured endpoints of that agent, deduplicating and rejecting expansion. Plugins must only call it after protocol authentication. listPending/claim/complete/fail delegate with that immutable scope; claim generates a fresh secure token while storage makes claimKey replay idempotent. Complete uses getInbound only to construct frozen target/chunks; completeAndEnqueue atomically rechecks scope/token/final uniqueness. Complete never accepts a reply destination. Agent tool responses must project snapshots to safe external fields; full endpoint.config is internal and may contain private URLs/SecretRefs.

`chunkText(text,max,unit)` supports UTF16 units, codepoints and UTF8 bytes without splitting a Unicode scalar; lone surrogates and an impossible single-scalar limit reject. Each chunk gets `<deliveryUUID>:<index>` as its durable idempotencyKey and `state:null`. Plugins needing protocol sequence CAS allocate through their bound StateStore before external send; they must reuse that allocation and persisted chunk identity on retry. State namespaces are plugin metadata ID + account ID (channels) or agent kind (agents), not caller supplied.

`processDue()` runs one bounded sequential batch and prevents overlap within the runtime. Storage obtains FIFO endpoint work and atomic leases; core never implements an in-memory queue. It requests one lease at a time so a slow earlier call cannot expire queued work. Dispatch receives original frozen endpoint config, sends receive a single persisted chunk and target. Calls have AbortSignals and timeout races; thrown/invalid results or timeouts become unknown and stop automatic effects. Storage can safely recover expired sends for accounts declaring idempotentSend using the same chunk keys. Exact lease token/version is forwarded to settleAttempt; concurrent claim/final/requeue may make settlement conflict. Transport abort cannot undo an external effect and plugins must respect signals.

Defaults: batchSize32, batchDurationMs30000, callTimeoutMs10000, leaseMs30000, maxAttempts8, retryBaseMs1000, retryMaxMs300000, notificationIntervalMs60000, maxTextBytes1048576, maxContextBytes65536, maxHttpBodyBytes2097152. Lease exceeds timeout. Retryable delays clamp to [retryBaseMs,retryMaxMs]; absent delay uses exponential backoff. Accepted dispatch renews after notificationIntervalMs while unclaimed. Accepted/retryable attempts exhaust into rejected diagnostic `retry_budget_exhausted`, preserving records for explicit recovery. Outbound attempt budgets apply to the current chunk: storage resets attempts after successful advancement. Unknown remains unknown. Claimed requests never get automatic dispatch or timeout release. Storage FIFO and recovery semantics are independently tested against real databases.

`status(filter?)` returns database stats/paginated request+delivery records and connection components. This API is administrative and includes message content: CLI must avoid exposing it on public HTTP or logging it. `health` checks storage/version/connectivity and catches driver errors; `readiness` also checks accepting and last worker failure. Connection degradation is visible in status separately. CLI must run/supervise the worker and check loop freshness. `cleanup({before,limit})` delegates durable retention after bounded input checks, preserving unfinished/undelivered work by the Storage contract. `requeue({kind,id,expectedVersion,acknowledgeUnknown})` delegates exact-version explicit recovery; it never runs remote cancellation. Unknown recovery must be explicitly acknowledged.

Observe is wrapped in an exception-safe facade. Core uses finite counters/duration-in-seconds/gauges aligned with observability-standard, short ingest/claim/complete/fail/dispatch/send spans and safe diagnostic fields. Ingest persists its new local span context (or incoming context); worker stages link to it. Successful batches refresh backlog via real Storage.getStats. Failed stats refresh keeps previous values and marks storage_stats_stale; exporter failures never alter business state/readiness. Nothing here proves live account compatibility; local protocol E2E and real storage validation are delivery evidence.
