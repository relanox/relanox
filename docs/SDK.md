# SDK v1 implementation contract

`packages/sdk/src/index.ts` is the executable contract. All methods returning promises must finish their durable write before resolving. Times use integer Unix epoch milliseconds; durations use milliseconds. JSON is serializable, excludes undefined, and carries only platform protocol context. No SQL or transaction callback is exposed.

## Assembly and scope

Create one ChannelPlugin instance and ChannelHost per account. Account IDs are globally unique. Channel setup receives the validated static account and plugin-specific config. Secrets remain environment references in config and are resolved by the assembly/plugin; never copy credentials into request snapshots. Endpoint snapshots preserve the original destination/options and SecretRefs, never resolved values. Credential rotation changes the referenced environment value; a binding or destination change cannot redirect old requests. Dispatch resolves SecretRefs from the frozen endpoint config. Agent instances are per agent kind; setup receives that agent's endpoints and validated agent-wide config. Dispatch receives the frozen endpoint's own config.

ChannelHost is bound by core to its account and rejects mismatching source/target/channel. Core resolves bindings by account/chat/thread, checks account and optional binding sender allowlists, and freezes the target and endpoint. AgentHost.forPrincipal is invoked only after plugin protocol authentication. Core intersects the authenticated principal's endpoint IDs with configured endpoints for that agent. Request bodies cannot expand this scope. StateStore is bound to plugin/account (agent owner for subscriptions); routes are mounted beneath a core-controlled plugin namespace. Channel/Agent never receive Storage.

Plugin validateConfig throws on invalid unknown input; no Zod type leaks into SDK. HTTP handlers use Web Request/Response. Setup registers handlers but does not listen. Long connection start returns after initialization; stop closes connections. Capabilities declare text size unit and durable idempotency. Core splits final text with these limits before committing outbound. Plugin send receives exactly one persisted chunk and must reuse its idempotencyKey and state. Protocol sequence allocation uses namespaced StateStore CAS before external send; chunk state is reserved for immutable preparation at completion.

## Storage transactions

- acceptInbound uses the tuple channel/account/eventId as a unique key. Replay returns original requestId, even if a caller generates another ID. Pending starts at version 1 with dispatch dueAt = acceptedAt and zero attempts. Records are deep serialized snapshots; caller mutations cannot change them.
- listPending returns ordered pending snapshots within endpointIds, bounded by limit; FIFO order is acceptedAt then requestId. claimRequest atomically checks scope and endpoint exclusivity. An existing claim or already-started notification owns the endpoint until finalization or explicit recovery. A started notification has a dispatch lease, a nonzero attempt count, or unknown/rejected dispatch status. Newly accepted requests cannot preempt it even if their timestamp/ID sorts earlier. Among unstarted pending requests, only the earliest (acceptedAt, requestId) can claim. Same request/claimKey returns the existing token and replay=true; a different key or another active endpoint claim returns busy. Completed/failed return not_pending. claim tokens are supplied by core secure randomness and remain valid until finalization or explicit requeue, never until a timeout.
- completeAndEnqueue validates scope and current claimToken, commits the unique final and outbound together, and releases endpoint serialization. Replay with identical resultId/text and current valid claim returns original deliveryId, replay=true. Same resultId with different text or a second final conflicts. Outbound must reference that request/result and frozen target, currentChunk=0, empty receipts, pending status and version=1. Storage verifies those invariants rather than trusting caller destinations. Final result IDs are globally unique. fail requires scope/current token and records terminal error; duplicate matching failure is idempotent. Next endpoint request becomes eligible without an in-memory wakeup.
- takeDue atomically obtains token/version/expiresAt leases and increments the durable version. Dispatch only chooses the earliest unfinished pending request for an endpoint; claimed requests block later requests and never dispatch. accepted dispatch remains retry eligible at nextDueAt while unclaimed (push notification may need renewal), with limits decided by core. Pull endpoints are claimed directly and excluded from automatic dispatch. Concurrent workers cannot obtain the same unexpired lease.
- Lease expiry is an uncertain external effect. Expired dispatch becomes unknown; expired send becomes unknown unless its account ID is in safeRetryAccountIds, where the same persisted chunk identity can retry. Unknown records are not selected automatically. settleAttempt checks the exact lease token/version and cannot overwrite a new claim/final/requeue. It clears the lease and updates attempt count/outcome. A sent chunk appends its receipt, advances currentChunk, and resets attempts to zero atomically; attempts count failures/transmissions for the current chunk, not already sent chunks; only all chunks sent marks delivery sent. Retryable retains index and identities; rejected/unknown stop automatic sends. nextDueAt is chosen by core, including bounded retryAfterMs. claim/final/requeue invalidate dispatch leases.
- requeue requires exact record version. Request recovery is allowed for claimed/failed/dispatch-rejected/dispatch-unknown, revokes claim token/final failure and resets dispatch due. Completed or intentionally redacted requests cannot rerun. Delivery recovery permits rejected/unknown, retains sent chunks and receipts, resets attempts to zero for a new retry budget, and resumes currentChunk. Unknown recovery requires acknowledgeUnknown=true; this acknowledges potential duplicate external effects. No remote cancellation is claimed.
- State CAS expectedVersion=null means create only; successful writes increment monotonically starting at 1. Delete requires exact version. Namespace tuple pluginId/ownerId/key is unique. State list is ordered by key, expiresBefore includes only entries with expiresAt <= bound, and combines prefix and expiry filters. State values are serialized snapshots.
- Admin list methods apply only their relevant status filter and optional endpoint scope; order by ID, exclusive afterId pagination. getStats uses database aggregates, unknown counts pending requests with unknown dispatch and unknown deliveries; a durable agent claim resolves notification uncertainty, undelivered includes pending/rejected/unknown deliveries. oldestPendingAt is absent when none. cleanup redacts text/context from completed requests only when outbound is sent and older than before; failed requests may be redacted when older than before. Preserve source dedup keys, final identity, and minimal result digest/equality information required for replay/conflict; never purge unfinished or undelivered work. redactedAt signals empty text/context tombstones. Implementations may retain a digest internally without adding a business table.
- migrate is explicit and idempotent. health checks migration currency and connectivity. close releases resources; correctness never depends on close flushing.

Storage reports business outcomes with unions. Driver/I/O failures reject, so upstream must not ACK. expectedVersion and lease fencing protect local persistence, not exactly-once remote effects.

## Observability and tooling

Observability is synchronous and best effort. Facades must isolate exporter failures. Logs accept only LogFields; metric labels never accept request/user/chat IDs. Span exposes optional serializable context for durable stage links, is short and ends once; trace context is correlation, not authorization. `noopObservability` is the production disabled facade. Metrics handler is mounted on the management listener by CLI, never implicitly public.

Node 24, ESM, pnpm 10.33.4 and exact compiler/tool versions are pinned. Packages declare `workspace:*` dependencies and use the shared tsconfig with src/dist; pnpm recursive builds topologically. Root Vitest discovers tests under tests/packages/plugins/apps. Shared storage cases belong under tests/contracts and are called by real storage suites; helper files do not match test discovery. Each test requires its task rationale before being written. T01 adds no type/no-op tests; compilation verifies contracts, and subsequent tasks test observable runtime behavior.
