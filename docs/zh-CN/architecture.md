# 消息如何到达 Agent

Relanox 将你的聊天账号连接到已有的 dot 或 Grok Bot。用户在配置好的会话中发送消息，Agent 收到消息后处理，回复再回到原来的会话。

## 跟着一条消息看流程

1. **用户发送消息。** 渠道连接从平台接收文字和支持的附件。
2. **Relanox 检查使用权限。** 发送者必须在账号的允许名单中，会话也必须绑定到一个 Agent。线程需要自己的匹配绑定；绑定还可以设置更小的允许名单。
3. **Relanox 保存消息。** 在确认接收之前，文字、附件和原来的回复位置会保存到 SQLite 或 PostgreSQL。同一条消息重复到达时，会自动识别。
4. **Agent 收到通知。** Relanox 将消息和附件信息发送给 dot 或 Grok。Agent 可以读取附件，并在自己的服务中准备回复。
5. **回复回到原会话。** Agent 请求 Relanox 发送文字或支持的媒体。Relanox 先保存回复，按平台长度限制拆分长文字，再发送并记录结果。

渠道允许多次回复时，Agent 可以先发一条进度说明，再发最终答案。企业微信 HTTP 回调每条来信只允许一次回复，因此该模式只发送最终答案。收到问题后，Agent 需要时间处理；完成后，回复会出现在原会话。回复迟迟没有出现时，参阅[消息状态与恢复](reference/core.md)。

## 重启之后会怎样？

已保存的工作保留在配置的数据库中。Relanox 再次启动后，会继续处理等待通知或发送的消息。请将 SQLite 文件放在持久存储上，或使用持久化的 PostgreSQL 数据库。

请保持服务运行，以便及时接收新消息。遇到中断后，先检查渠道连接，再把仍需回答的问题重新发送。

## 旧消息会发到哪里？

每条已接收消息都保留原来的 Agent 和回复位置。修改绑定只影响新消息，不会把已经保存的工作转发到别处。更换账号密钥后，更新环境变量并重启服务。保存的待处理消息也会使用更新后的密钥。

Relanox 根据收到的原始消息确定回复位置，并核对 Agent 的访问权限。

## 需要运行哪些服务？

准备一台运行 Relanox 的电脑或服务器，以及一个可用的 dot 或 Grok Bot。开始使用时可选择 SQLite，数据保存在本机文件中；也可以连接 PostgreSQL。有些渠道需要公开的 HTTPS 地址来接收回调或提供媒体下载；另一些渠道主动连接平台。各[渠道指南](channels/index.md)说明了具体要求。

两种云端 Agent 都需要公网可访问的 HTTPS 地址连接 MCP，包括主动连接平台的渠道。

服务另有一个本机管理地址，用于健康检查和指标采集。请保持该地址私有。标准运行日志不包含消息正文或凭据；管理命令仅在你明确要求时显示消息正文。
