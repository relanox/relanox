# 收发图片和文件

连接好渠道和 Agent 后，就可以在聊天里发送图片、音频、视频或文件。比如发一张截图请 Agent 解释，上传文档请它整理要点，或让它把生成的图片发回当前聊天。

先用一张小图片试一遍：发送图片并写上“请描述这张图片”。Agent 能读取附件并回复后，再尝试你需要的文件类型。

## 发送附件

在[连接配置器](connect.md)选定的聊天里发送一张小图片，请 Agent 描述它。无需为附件单独设置回复说明或连接。发送音频、视频和其他文件前，查看[对应渠道指南](channels/index.md)支持的格式，以及是否需要时长或封面。

不超过 64 KB 的 UTF-8 纯文本、Markdown、CSV、TSV 和 JSON 文件可以通过连接直接读取。更大的文件及其他格式需要 Agent 下载，能否读取还取决于它的网络和文件支持。

## 让 Agent 理解语音消息

可以按需开启[腾讯云语音识别](reference/configuration.md#speech-to-text)。Relanox 会为发给 dot、Grok 或 Muse 的音频消息追加转写文字，并保留原音频。未配置或识别失败时仍转发原音频。这项转写不会分析视频或其他文件。

## 接收 Agent 生成的文件

可以先试：“创建一个写着今天待办事项的小文本文件，作为附件发到当前聊天。”确认原聊天收到可以下载的文件，而不只是文件名或“文件已准备好”的文字。

请 Agent 把生成的文件发回当前聊天。dot 可以发送工作区中的文件；Grok Bot 和 Muse 可以先把云电脑里的文件上传到 Relanox，再作为附件发送。也可以使用能直接下载的公开 HTTPS 链接。

连接会提供上传说明，无需另配文件服务或回复说明。上传只会保存文件，Agent 还需要将它发送到聊天。

文件归属于接收或上传时选定的聊天。请让 Agent 将生成文件上传到实际接收它的聊天；发送前可以请它检查可用聊天和支持的文件类型。

Grok 可能要求你确认从云电脑上传生成的文件。允许前核对文件名和自己的 Relanox 地址；等待确认期间，原聊天不会收到附件。

在 LINE、Google Chat、Microsoft Teams、Mattermost 和 QQ 中将图片与文字一起显示时，需要能通过公网 HTTPS 地址访问 Relanox。LINE 音视频和 Teams 群聊或频道中的独立大图片也使用该地址。使用配置器中填写的地址，按[部署与日常管理](operations.md)让服务可访问。Teams 私聊可能要求你确认接收文件。IRC 支持文字聊天。

Relanox 下载链接通常有效 24 小时，持有有效链接的人可以下载文件，请只分享给预期收件人。

## 把图片放在段落之间

请 Agent 把图片放在对应的解释旁边。可以使用你发来的图片，也可以使用它生成的文件。没有放入解释中的图片会显示在文字之后。

显示方式取决于渠道。部分渠道可以将文字和图片一起显示，其余渠道按请求顺序发送独立消息。企业微信 HTTP 回调回复先显示文字，再显示图片；IRC 仅支持文字。可以请 Agent 检查所选聊天的显示方式和限制。语法和渠道细节见[按 Markdown 顺序发送媒体](reference/media.md#ordered-markdown-media)。

## 选择合适的文件大小

默认每个附件和单条消息合计均不超过 100 MB，最多 10 个附件。聊天平台或其 SDK 可能有更低限制。先使用小文件测试；文件过大时，先压缩或拆成几次发送。

调整大小限制或下载链接有效期的方法见[媒体配置与协议](reference/media.md)，其中也保留了手动 JSON 设置和 Agent 使用的工具说明。

## 文件保存在什么地方

Relanox 把已接收的附件和 Agent 上传的文件保存在配置的数据库中。备份数据库会同时备份这些文件，因此请为图片和视频留出存储空间。

日常清理会删除符合条件的旧附件，相关下载链接也会随之失效。选择清理时间时，为收件人下载文件留出时间。具体命令见[备份与清理](operations.md)。

## 附件没有发出来时

1. 先发一条文字，确认账号和 Agent 已接通。
2. 使用小图片重试，检查是否与文件大小或格式有关。
3. 如果由 Agent 生成文件，检查上传是否完成，以及 Agent 是否把附件发到了当前聊天；使用下载链接时，确认链接能直接下载。
4. 使用 LINE、Google Chat 或 Teams 群聊图片时，检查公网 HTTPS 地址。
5. 查看[消息状态与恢复](reference/core.md)，按提示处理待发送的消息。
