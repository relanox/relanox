# QQ 机器人

通过官方 QQ 机器人，在私聊和 @ 机器人的群聊中使用 Agent。

## 准备账号

在 QQ 机器人平台创建并启用机器人，记录 App ID，将 Client Secret 存入环境变量，并获得 `GROUP_AND_C2C_EVENT` 权限。根据应用的测试或发布状态，向对应用户和群组开放机器人。

## 在配置器中填写

打开[连接配置器](../connect.md)，选择 **QQ 机器人**，填写上一步取得的账号信息。凭据变量名保持默认，按照下载后生成的教程设置实际密钥。将下文取得的发送者 ID 填入「允许使用的用户 ID」，会话 ID 填入「聊天 ID」，有话题时填写「话题 / 线程 ID」，并选择「接收 Agent」。多个允许用户用英文逗号分隔。

| 配置器字段 | 填写内容            |
| ---------- | ------------------- |
| 应用 ID    | 上一步取得的应用 ID |

将下载的配置保存为 `relanox.json`，并按接入教程在服务器上设置密钥。完成下方的平台连接设置后启动或重启服务，并按「发送第一条消息」验证。手写配置与协议参数见[技术参考](../reference/channels.md#qq)。

请机器人管理员准备下面列出的用户和会话 ID，再填写配置。管理员可以从已有的机器人消息记录中核对这些值。使用平台分配的 ID，而非聊天中显示的名称。

私聊的允许发送者和绑定 「聊天 ID」均使用 `author.user_openid`。群聊允许发送者使用 `author.member_openid`，「聊天 ID」使用 `group_openid`。从机器人消息事件取得这些值；它们是平台 OpenID，与显示的 QQ 号码不同。

QQ 默认使用正式环境；测试账号在配置器的 QQ 环境选择 sandbox。

向已绑定目标主动发送时，在下载配置的账号 `config` 中加入 `recipientTypes`：将「聊天 ID」映射为私聊用户的 `c2c` 或群组的 `group`。这只提供原生地址类型，不会授予主动发送权限。来信回复窗口有效时，Relanox 使用被动回复；没有有效窗口时使用主动消息。平台权限、额度和接收方设置是否允许发送，由 QQ 判定。「话题 / 线程 ID」留空。参见[手写配置示例](../reference/channels.md#qq)。

## 启用连接

Relanox 启动后会自动通过 WebSocket 连接，保持进程运行及访问 QQ API 和网关的出站网络。

## 发送第一条消息

私聊发送“你好”，或在绑定群组中 @ 机器人。先请它简短回复：平台为每条私聊输入提供 60 分钟、4 条回复额度，为每条群聊输入提供 5 分钟、5 条回复额度。

## 图片和文件

可发送原生图片、音频、视频和文件，生成的回复通过 QQ 附件发送。准备 PNG/JPEG 图片、MP4 视频、SILK 音频或普通文件。QQ 限制为图片/音频 20 MB、视频 30 MB、文件 200 MB；Relanox 默认 25 MiB 限制可能更低。回复文字与各个附件分别消耗回复额度。

附件下载失败时，消息仍会带着图片远程 URL、文件/视频描述，或 QQ 提供的语音识别文字继续到达 Agent。没有识别文字的语音会保留转写不可用提示。其他成功下载的附件仍可读取；图片 URL 可能过期，保留链接不保证能读取图片内容。

## 常见问题

网关拒绝连接时，检查机器人发布状态、应用凭据及事件权限。群消息缺失时，@ 机器人并核对群组/成员 OpenID。QQ 拒绝主动消息时，检查机器人平台权限和接收方设置。主动消息不可用时，发送新问题以打开被动回复窗口。

从包含 `allowProactive` 的旧配置升级时，先删除该字段，再启动新版。Relanox 不再提供 QQ 主动消息开关。
