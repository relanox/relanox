# 飞书 / Lark

将飞书或 Lark 的企业自建应用机器人连接到 Agent。

## 准备账号

创建企业自建应用，启用机器人能力，授予接收消息、发送消息和资源访问权限。记录 App ID 和 tenant key；将应用密钥、事件 Verification Token 和 Encrypt Key 存入接入教程列出的环境变量。Lark 用户在「平台域」选择 lark。

## 在配置器中填写

打开[连接配置器](../connect.md)，选择 **飞书 / Lark**，填写上一步取得的账号信息。凭据变量名保持默认，按照下载后生成的教程设置实际密钥。将下文取得的发送者 ID 填入「允许使用的用户 ID」，会话 ID 填入「聊天 ID」，有话题时填写「话题 / 线程 ID」，并选择「接收 Agent」。多个允许用户用英文逗号分隔。

| 配置器字段               | 填写内容             |
| ------------------------ | -------------------- |
| 应用 ID                  | 上一步取得的应用 ID  |
| 租户标识                 | 上一步取得的租户标识 |
| 平台域（feishu 或 lark） | 初始值：`feishu`     |

将下载的配置保存为 `relanox.json`，并按接入教程在服务器上设置密钥。完成下方的平台连接设置后启动或重启服务，并按「发送第一条消息」验证。手写配置与协议参数见[技术参考](../reference/channels.md#feishu)。

请机器人管理员准备下面列出的用户和会话 ID，再填写配置。管理员可以从已有的机器人消息记录中核对这些值。使用平台分配的 ID，而非聊天中显示的名称。

消息事件的发送者 `open_id` 填入「允许使用的用户 ID」，`message.chat_id` 填入「聊天 ID」。事件头中可取得 `tenant_key`。话题绑定使用 `message.thread_id`。普通回复可能有 `root_id` 而没有 `thread_id`；此时只绑定聊天 ID，不填写话题 ID。

普通会话目标使用配置的聊天 ID 和应用权限。向消息串内发送还需要已验证事件中的真实消息锚点，且账号、聊天和消息串必须匹配。Relanox 连接后，在所选消息串内发送一条消息以建立锚点；仅填写消息串 ID 不足以发送。

## 启用连接

使用事件订阅 v2.0，将地址填为 `https://relay.example.com/channels/feishu-main/events`，订阅 `im.message.receive_v1`，并配置相同的 Verification Token 和 Encrypt Key。验证回调前启动 Relanox，然后发布应用变更，向使用者开放机器人。

## 发送第一条消息

打开与机器人的会话，或将它加入绑定群组并 @ 它发送“你好”。发送者需在应用可用范围和允许发送者列表内。

Agent 提供 `reply.requestId` 时，回复引用对应的原始来信，消息串内也会选择该条消息。不提供 `reply` 时，向会话普通发送；消息串发送使用已建立的根消息锚点，保持在原消息串内。

## 图片和文件

提问时可发送图片、音频、视频、文件或富文本消息。授予资源下载和上传权限，如 `im:resource` 或适用的上传权限。回复图片上传上限为 10 MB，其他上传为 30 MB，同时受 Relanox 限制。

## 常见问题

回调验证失败时，核对双方 Token 和 Encrypt Key。部分用户无法使用机器人时，检查已发布应用的可用范围。媒体传输失败时，检查资源权限，并按企业要求重新安装或发布权限变更。
