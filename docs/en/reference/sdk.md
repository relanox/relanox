# SDK v1 implementation contract

`packages/sdk/src/index.ts` is the stable public contract entrypoint. Definitions are organized by configuration, messages, plugin state, storage, observability and plugin hosts in adjacent domain modules. All methods returning promises must finish their durable write before resolving. Times use integer Unix epoch milliseconds; durations use milliseconds. JSON is serializable, excludes undefined, and carries only platform protocol context. No SQL or transaction callback is exposed.

## Assembly and scope

Create one ChannelPlugin instance and ChannelHost per account. Account IDs are globally unique. Channel setup receives the validated static account and plugin-specific config. Secrets remain environment references in config and are resolved by the assembly/plugin; never copy credentials into request snapshots. Endpoint snapshots preserve the original destination/options and SecretRefs, never resolved values. Credential rotation changes the referenced environment value; a binding or destination change cannot redirect old requests. Dispatch resolves SecretRefs from the frozen endpoint config. Agent instances are per agent kind; setup receives that agent's endpoints and validated agent-wide config. Dispatch receives the frozen endpoint's own config.

ChannelHost is bound by core to its account and rejects mismatching source/target/channel. Core resolves bindings by account/chat/thread, checks account and optional binding sender allowlists, and freezes the target and endpoint. AgentHost.forPrincipal is invoked only after plugin protocol authentication. Core intersects the authenticated principal's endpoint IDs with configured endpoints for that agent. Request bodies cannot expand this scope. StateStore is bound to plugin/account (agent owner for subscriptions); routes are mounted beneath a core-controlled plugin namespace. Channel/Agent never receive Storage.

Plugin validateConfig throws on invalid unknown input; no Zod type leaks into SDK. HTTP handlers use Web Request/Response. Setup registers handlers but does not listen. Long connection start returns after initialization; stop closes connections. Capabilities declare text size unit and durable idempotency. Core splits each reply text with these limits before committing outbound. Plugin send receives exactly one persisted chunk and must reuse its idempotencyKey and state. Protocol sequence allocation uses namespaced StateStore CAS before external send; chunk state is reserved for immutable preparation at message enqueue.

## Media contracts

`MediaUpload` carries in-memory bytes with kind, MIME type, filename and optional duration/preview ID. `MediaReference` adds request-owned UUID, byte size and SHA-256; snapshots and outbound messages use references. `StoredMedia` pairs the reference with bytes. `ChannelPlugin.capabilities.media` explicitly lists accepted receive/send kinds. `SendInput.media` and optional `preview` are resolved and checked by core, while media chunks have empty text. Channel adapters must preserve native format/permission limits.

`Storage.acceptInbound(snapshot, media)` atomically commits incoming bytes and the snapshot. `ScopedAgentHost.media.read({requestId,mediaId})` authorizes the endpoint scope without a task token. `sendMessage({replyTo,text,idempotencyKey?,attachments?})` accepts received media IDs, inline `MediaUpload` values, or a generated `{media,preview}` pair. Storage's `enqueueMessage` checks request/agent/endpoint scope and the frozen target, then commits generated assets, message identity and outbound chunks in one transaction. Media and preview references remain owned by the input. No separate agent upload operation exists.

`ChannelHost.media.publish` optionally issues durable, expiring URLs scoped to its account and request. `mountHttp` can opt into a bounded larger body only with an authorization callback that runs before buffering. Agent binary routes use this facility with signed download URLs; ordinary routes retain their normal body cap. See [Media transfer](../media.md).

## Storage transactions

- `acceptInbound` deduplicates channel/account/eventId and returns the original requestId on replay. A new record contains only snapshot, version 1, dispatch state and optional redactedAt. Dispatch starts `due` at acceptedAt with zero attempts. Caller mutations cannot alter serialized records.
- `enqueueMessage` verifies immutable endpoint/agent authorization, input availability, message identity, frozen target and chunk/media consistency. It commits all new assets and one outbound record atomically. Identical message identity/content returns the original deliveryId with replay=true; changed content conflicts. Outbound records use `messageId`, version 1, pending status, currentChunk 0 and empty receipts. Multiple independent messages can refer to the same input.
- `takeDue` acquires short token/version/expiresAt leases atomically, advances versions and orders due work by durable time/identity. Different inputs sharing an endpoint do not block one another. Replies to one input follow durable insertion order: only its earliest pending delivery is selected, and an earlier unknown delivery holds later replies until manual recovery. Rejected delivery releases later replies. Accepted notification receipt is terminal; only due notifications and pending sends are selected. Concurrent workers cannot acquire the same live lease.
- Expired dispatch becomes unknown. Expired sends become unknown unless safeRetryAccountIds permits the same chunk identity to retry. `settleAttempt` requires the exact lease token/version and cannot overwrite newer settlement/requeue. It clears the lease and records the outcome. A sent chunk appends its receipt, advances currentChunk and resets current-chunk attempts to zero; only all chunks sent makes a delivery sent. Retryable preserves chunk identity; rejected/unknown stop automatic effects.
- `requeue` requires the current version. Accepted/rejected/unknown notifications can become due again unless redacted; delivery recovery permits rejected/unknown, retains sent chunks/receipts, resets the current retry budget and resumes currentChunk. Unknown recovery requires acknowledgeUnknown=true. Notification recovery does not cancel remote work or revoke the input's reply authority.
- State CAS expectedVersion=null creates only; successful writes increment monotonically from 1 across deletion/recreation. Exact-version deletion keeps an invisible version fence. Namespace pluginId/ownerId/key is unique. Ordered lists combine prefix/expiry filters; expiry includes expiresAt <= bound. Values are serialized snapshots.
- Admin lists use the relevant dispatchStatus/deliveryStatus, optional endpoint scope and exclusive afterId pagination by ID. `getStats` aggregates pending **due notifications**, undelivered pending/rejected/unknown deliveries and unknown notification/delivery effects. No claimed count exists; oldestPendingAt is absent when no notification is due.
- Cleanup redacts eligible old message content and removes eligible media while retaining source deduplication and message equality information for replay/conflict. It protects due/unknown notifications and every undelivered outbound message. Empty text/context with redactedAt is a tombstone; it cannot accept new replies.
- `initialize` creates the current schema idempotently. `health` checks required tables/connectivity without initialization; `close` releases resources, and durability never depends on it.

Storage returns typed business outcome unions; driver/I/O failures reject so ingress must not ACK. Version and lease fences protect local state, not exactly-once external effects.

## Observability

Observability is synchronous and best effort. Facades must isolate exporter failures. Logs accept only LogFields; metric labels never accept request/user/chat IDs. Span exposes optional serializable context for durable stage links, is short and ends once; trace context is correlation, not authorization. `noopObservability` is the production disabled facade. Metrics handler is mounted on the management listener by CLI, never implicitly public.
