# Core assembly API

`@relanox/core` depends only on SDK, Hono and Zod. `createCore` receives `{ config, storage, channels, agents, observe?, worker?, media? }`. It does not create storage, initialize its schema, start listeners/timers, resolve credentials, or start/stop plugins. CLI initializes storage on run before checking health, assembles plugins, creates core, starts connections with a process AbortSignal, and calls processDue periodically. Offline diagnosis only inspects storage. Shutdown sets accepting=false, stops the background loop/connections, closes storage and bounded observability export.

## Plugin assembly and configuration

`channels` is a ReadonlyMap keyed by configured account ID with one ChannelPlugin instance per account. `agents` is keyed by `dot`/`grok`, one instance per kind. Plugin config generics are erased to unknown at assembly; typed plugin factories still validate their own schemas. Metadata must match configured kind, SDK major 1 and node runtime. All account and **per-endpoint** agent configs are validated before any setup. Account setup gets the parsed plugin configuration and a copy of its original static account. Agent setup gets all its original endpoint configs and `{}` as the third argument; per-endpoint validateConfig never validates `{}` as an agent-wide configuration. Agents validate their frozen endpoint configs again as needed when dispatching.

`validateConfig(unknown)` validates the strict SDK-shaped static JSON. IDs are safe URL namespace segments, bindings reference existing accounts/endpoints and unique `(accountId,chatId,threadId)` tuples, and allowlists are explicit nonempty sender IDs. A missing binding rejects; an account allowlist and optional binding allowlist must both permit the sender. There is no implicit thread fallback/wildcard. Configuration contains only static JSON; plugin schemas must require SecretRefs for credential fields. `secretRefSchema` and `resolveSecretRef(ref,environment)` let assembly/plugins resolve at use, without core reading process.env. Core persists copies of **original** endpoint JSON/options/SecretRefs and durable targets, not validator results or resolved secrets. Plugins must not put credentials into target.data/context. Configuration changes require process recreation; old persisted endpoints continue dispatching to the original destination while resolving current referenced environment values.

## HTTP and Hosts

HTTP mounts use `/channels/<accountId><path>` and `/agents/<agentId><path>`; path `/` mounts the namespace root. Example channel `/webhook` becomes `/channels/bot/webhook`; agent `/mcp` becomes `/agents/grok/mcp`. Plugin handlers see the full original URL, including this prefix. Mount paths accept literal safe segments and a terminal `*`, never traversal/query/fragment. Duplicate routes reject setup. Core handles route errors with a redacted 500. HTTP bodies are buffered as exact bytes up to maxHttpBodyBytes, including chunked/dishonest Content-Length input; oversized inputs return 413, incomplete bodies hit callTimeoutMs and return 408. No signature decoding or reserialization occurs. Protocol plugins authenticate before Host calls and enforce their transport-specific body/host/origin/time limits. Management health/metrics routes are mounted by CLI on its separate listener, not exposed by the business fetch API.

ChannelHost pins source+target account/channel, validates bounded Unicode text and serializable context, checks allowlists/binding and waits for acceptInbound before returning. Storage owns stable event deduplication. AgentHost.forPrincipal intersects authenticated endpoint IDs with configured endpoints of that agent, deduplicating and rejecting expansion. Plugins must only call it after protocol authentication. `sendMessage({replyTo,text,idempotencyKey?,attachments?})` uses that immutable scope. It reads the input only to construct frozen chunks/target; `Storage.enqueueMessage` atomically rechecks authorization, message identity and media invariants. No supplied destination is accepted. Identical content deduplicates by default; explicit keys support stable retries and intentional identical distinct sends. The same input can receive multiple independently queued messages. `media.read({requestId,mediaId})` checks the same endpoint scope. Agent responses and push payloads expose safe fields, never endpoint.config or private SecretRefs.

`chunkText(text,max,unit)` supports UTF16 units, codepoints and UTF8 bytes without splitting a Unicode scalar; lone surrogates and an impossible single-scalar limit reject. Each chunk gets `<deliveryUUID>:<index>` as its durable idempotencyKey and `state:null`. Plugins needing protocol sequence CAS allocate through their bound StateStore before external send; they must reuse that allocation and persisted chunk identity on retry. State namespaces are plugin metadata ID + account ID (channels) or agent kind (agents), not caller supplied.

## Media boundaries

Core validates each inbound upload before committing its bytes with the request. It accepts empty text only when media exists and enforces channel receive kinds, MIME/kind consistency, filenames, byte/count budgets and integrity. Each scoped send accepts ordered received-media IDs or generated uploads, including an atomic media/preview pair, verifies request ownership and previews, checks send capabilities and commits media chunks after text. The worker resolves stored bytes immediately before each native send.

Optional `media` config is validated by `validateMediaOptions`; it contains `publicBaseUrl`, optional `urlLifetimeMs` and explicit `allowInsecureLocalhost`. The publisher mounts `/media/<accountId>/<requestId>/<mediaId>` with opaque expiring access tokens stored in a core-owned namespace. Plugin hosts can only publish their own account's request assets. Signed agent download routes independently authorize before using a larger body limit; ordinary HTTP routes retain `maxHttpBodyBytes`. See [Media transfer](../media.md) for deployment and retention requirements.

## Worker batches

`processDue()` runs one bounded sequential batch and prevents overlap within the runtime. Storage obtains due message work and atomic leases; core never implements an in-memory queue. It requests one lease at a time so a slow earlier call cannot expire queued work. Dispatch receives original frozen endpoint config, sends receive a single persisted chunk and target. Calls have AbortSignals and timeout races; thrown/invalid results or timeouts become unknown and stop automatic effects. Storage can safely recover expired sends for accounts declaring idempotentSend using the same chunk keys. Exact lease token/version is forwarded to settleAttempt; concurrent settlement/requeue may make settlement conflict. Transport abort cannot undo an external effect and plugins must respect signals.

Defaults: batchSize32, batchDurationMs30000, callTimeoutMs10000, leaseMs30000, maxAttempts8, retryBaseMs1000, retryMaxMs300000, maxTextBytes1048576, maxMediaBytes26214400, maxTotalMediaBytes52428800, maxAttachments10, maxContextBytes65536, maxHttpBodyBytes2097152. Lease exceeds timeout. Retryable delays clamp to [retryBaseMs,retryMaxMs]; absent delay uses exponential backoff. Accepted dispatch is terminal, regardless of whether an agent sends a reply. Retryable attempts exhaust into rejected diagnostic `retry_budget_exhausted`, preserving notifications for explicit recovery. No endpoint serialization or automatic notification renewal occurs. Outbound attempt budgets apply to the current chunk and reset after successful advancement; unknown stays unknown until explicit recovery.

## Administration and observability

`status(filter?)` returns database stats/paginated request+delivery records and connection components. This API is administrative and includes message content: CLI must avoid exposing it on public HTTP or logging it. `health` checks storage health/connectivity and catches driver errors; `readiness` also checks accepting and last worker failure. Connection degradation is visible in status separately. CLI must run/supervise the worker and check loop freshness. `cleanup({before,limit})` delegates durable retention after bounded input checks, preserving unfinished/undelivered work by the Storage contract. `requeue({kind,id,expectedVersion,acknowledgeUnknown})` delegates exact-version explicit recovery; it never runs remote cancellation. Unknown recovery must be explicitly acknowledged.

Observe is wrapped in an exception-safe facade. Core uses finite counters/duration-in-seconds/gauges aligned with observability-standard, short ingest/enqueue_message/dispatch/send spans and safe diagnostic fields. Ingest persists its new local span context (or incoming context); worker stages link to it. Successful batches refresh backlog via real Storage.getStats. Failed stats refresh keeps previous values and marks storage_stats_stale; exporter failures never alter business state/readiness.
